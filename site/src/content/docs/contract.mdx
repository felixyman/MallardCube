---
title: Serving contract (0.1, unstable)
description: The source-neutral contract.yaml — what it expresses, and why it carries no SQL
---

The serving contract describes a model's **meaning** — grain, keys,
relationships and measure declarations — in one source-neutral file. It is the
format generators write (sqlmesh, dbt), the qualifier checks, and the source
the proxy config projects from.

**It is unstable.** At `0.x`, core fields may change between minor versions
with a changelog entry and no deprecation window; `1.0` is the commitment
point, tied to the certification matrix. Prototype new fields under
`annotations:`, which the proxy ignores and generators preserve — a field earns
core status only once a qualifier check exists behind it.

## What it deliberately does not contain

No SQL, and no engine specifics. The contract states intent — "revenue is a sum
at the order grain", "this median is valid only at month × product" — while
execution lives in the generated proxy config. Anything engine-specific is a
declared serving hint, and a hint that is required but unused is a
qualification failure, never a guess.

## The shape

```yaml
contract_version: "0.1.0"
model: { name: upstream_marts, description: "Thin projection of the marts" }
grain:
  - { table: fact_orders, key: order_id, id: orders, measure_group: Orders }
  - { table: mart_lead_time_median_month, key: [year, month, product_key], id: lead_time_median }
dimensions:
  - { id: Date, table: dim_date, key: date_key, attribute: full_date, hierarchy_name: Calendar,
      date_role: true,
      levels: [ { name: Year, column: year }, { name: Month, column: month },
                { name: Full Date, column: full_date } ] }
relationships:
  - { fact: fact_orders, dimension: Date, columns: [order_date_key, date_key] }
measures:
  - { id: Revenue, source: { table: fact_orders, column: revenue }, aggregation: sum }
  - { id: On-time %, source: { table: fact_orders }, aggregation: ratio,
      expression: "sum(is_within_sla) * 100.0 / nullif(sum(is_order), 0)" }
  - { id: Median lead time, source: { table: mart_lead_time_median_month, column: median_lead_time },
      aggregation: max, valid_grain: [year, month, product_key] }
time_intelligence:
  date_dimension: Date
  flags: { ytd: ytd_flag, qtd: qtd_flag }
provenance: { source_system: sqlmesh, generator: mallard-contract/0.1.0 }
annotations: { note: "prototype fields live here until a check exists" }
```

`attribute` is the member value column Excel names members by (for a date role,
the leaf); `key` is the join key. Only `many_to_one` relationships are
expressible: anything else multiplies fact rows. Aggregations are **declared**,
not inferred, so a ratio is never emitted as if it were additive, and a
`valid_grain` value is an identity aggregate (`min`/`max`) that must never be
re-aggregated. `time_intelligence` binds the windows the engine serves (YTD,
QTD, MTD, prior-year YTD, current year) to upstream flag columns.

## Validating

```bash
# The schema (JSON Schema draft 2020-12) is checked in at schema/contract-0.1.json.
python3 scripts/contract_check.py                 # every fixture against the schema
mallard contract validate contracts/upstream_marts/contract.yaml
mallard contract validate contracts/upstream_marts/contract.yaml --json
```

Version rules and shape checks fail closed: an unknown core field is a hard
error, a duplicate mapping key is refused (YAML's last-wins would silently
rewrite the contract), a contract newer than the build supports refuses with an
upgrade hint, and an older version routes through an explicit migration — never
silent tolerance. The checked-in JSON Schema is the published shape and
carries the additivity rules as `if`/`then`; the validator is the enforcement,
and a 19-case conformance corpus runs both gates over the same contracts so
drift fails CI rather than shipping.

The runtime **never reads the contract**; it serves the projected config. See
the [model reference](/MallardCube/model/) for that format, and `plans/057` for the
contract's compatibility policy and the generator roadmap.
