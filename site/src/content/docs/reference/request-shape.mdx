An XMLA request is a SOAP 1.1 envelope whose body carries one `Discover` or
`Execute`. That much is in the specification. What clients actually trip over
is everything around it: which namespaces are checked, which restriction forms
exist, what an empty statement means, and how sessions attach to requests. Each
rule below was measured on a real SSAS instance, and the wording is what it
answers.

## Statements and sessions

The statement is where clients differ most: some send a full MDX query, some
send a `BeginSession` with an empty statement, and some send both. Sessions are
attached through the SOAP header, not the body.
